# 面试准备：中文大模型幻觉评测项目

> 用法：先背熟两个版本的项目介绍，再按模块过一遍问答。**所有数字都来自 `report/大模型幻觉评测报告.md` 和 `python scripts/reproduce_metrics.py` 的输出**，面试前最好再跑一遍脚本，对着输出说。答不上来就说「这个我没测，我会这样测……」，不要现编数字。

## 一、项目介绍

### 30 秒版

> 我做了一个中文大模型幻觉评测项目。用 Chinese SimpleQA 和 HalluQA 搭了一个 450 题的开发集，用 LLM 当裁判，逐版测 Qwen3-4B 和 8B 在提示约束、维基检索、重排、拦截这些改动下的幻觉率。最大的收获有两个：一是只看「拒答算没幻觉」会被骗——光改提示词，幻觉率能从 72.5% 降到 19.4%，但那是靠拒答 65.7% 的题换来的；二是检索是唯一同时显著减少幻觉、增加答对的一步。误导题我试了三种办法都没过事先定的判据，我把失败原因也都写进了报告。所有数字都能一条命令重算出来。

### 2 分钟版

> 这个项目最早是为一个大模型幻觉比赛做的练习。官方只给了一个公式：幻觉率 = 幻觉样本数 / 有效样本数，但没说拒答怎么算。我第一反应是：如果拒答不算幻觉，模型全拒答就是 0%。所以我从一开始就同时报三个数：拒答算有效的 HR、把拒答剔掉的 HR，还有答对数。
>
> 评测集用两个公开数据集分层抽了 450 题：Chinese SimpleQA 300 道事实短答题，HalluQA 150 道，其中一半是带错误前提的误导题。另外留了 3000 题当留出集，一直没动。裁判用 LLM，只依据标准答案判两个标签：有没有幻觉、是不是拒答。上裁判之前，先用 24 条人工标注的样例做验收。
>
> 实验是一版一版做的，每版都先写下假设和通过的判据。Qwen3-4B 原样作答，幻觉率 72.5%。加系统提示让它「不确定就说不知道」，幻觉率降到 19.4%，但拒答率到了 65.7%，答对数反而从 121 掉到 72——这一步只是把幻觉换成了拒答。加维基 BM25 检索后，答对涨到 250，幻觉 83，这是相邻版本里唯一让两边同时显著改善的一步。再加重排，答对到 267，幻觉持平，选为基线。
>
> 误导题是短板。我试了三种做法：泛化的「先挑错」提示，结果正常题也开始挑错，幻觉从 82 涨到 151；让模型自己判断题目有没有陷阱，拦住 19 个幻觉，却误拒了 67 道答对的题；写关键词规则，拦 14 个、误拒 7 个。三个都没过事先定的门槛，就停了，没有硬调。
>
> 最后做了一轮自审：裁判验收 24 条全对，听着很好，但置信下界只有 86%；14 个检验做多重比较校正后，有两个原来「显著」的结论不再显著。这些都写进了报告的局限部分。如果有更多资源，我第一步会在留出集上验证，再做人工标注，量化裁判和人的一致率。

## 二、高频问题与参考回答

### A. 项目动机与指标设计

**Q1. 为什么做这个项目？想解决什么问题？**
- 起因是一个大模型幻觉比赛的练习。官方只给了 HR = 幻觉样本 / 有效样本，没说拒答怎么计分。
- 想回答的问题是：在固定的小模型上，提示、检索、拦截这几类常见手段，各自能把幻觉降多少、代价是什么。
- 顺手搭了一套能复现的评测流程：开发集 → 作答落盘 → LLM 裁判 → 一键重算 → 报告。

**Q2. 你怎么定义「幻觉」？裁判具体输出什么？**
- 裁判只看问题、参考材料（标准答案 + 出处）和回答，输出两个布尔值：`hallucinated`（和材料冲突，或声称来源写了材料里没有的内容）、`refused`（明确表示答不了）。
- 两个可以同时为真：拒答的同时编了理由，记为「双标签」。V5 有 34 道这样的题。
- 提示词要求裁判只依据材料、不用自己的记忆，避免裁判拿它自己的错误知识来判。

**Q3. 为什么要报两种 HR？为什么还要答对数？**
- 「拒答算有效」口径：拒答算没幻觉，全拒答就能拿 0%，奖励过度拒答。V1 就是例子：19.4%，但拒答率 65.7%。
- 「拒答剔除」口径：只看模型选择作答的题，衡量「敢答的时候准不准」。V1 在这个口径下是 53.2%，比 p0 的 72.2% 低，但作答的题从 436 道缩到 154 道，有选择效应。
- 两个比例都能被拒答操纵，所以必须再看一个绝对数：答对数。V1 答对 121 → 72，一眼就能看出它不是真进步。
- 一句话：**比例看风险，绝对数看能力，三个一起看才不会被骗。**

**Q4. 你说的「答对」真的是答对吗？**
- 严格说不是。裁判只判幻觉和拒答，「答对」= 作答且没被判幻觉。答非所问、只答一半也会算进去。报告里 hqa-31 的 V3 回答语句不通，照样被判「答对」。
- 在 SimpleQA 上我用「标准答案是不是回答的子串」做了独立核对：V4 里规则没匹配上、但裁判判答对的有 39 道，抽查 15 道，13 道确实对（只是写法不同），2 道存疑。所以它大体接近正确，但不等于正确。
- 如果重做，我会让裁判单独输出一个「是否正确回答」的标签，或者叫它「非幻觉作答」，名字更准确。

**Q5. 开发集怎么构造的？为什么是这个配比？**
- `eval/make_dev.py` 用固定种子分层抽样：SimpleQA 300（6 个一级类各 50）、HalluQA Knowledge 60、Misleading 60、Misleading-hard 30，共 450 题；剩下 3000 题做留出集，从没用过。
- 配比是为了让误导题够测、又不让它主导总分。缺点是「全部」一栏的 HR 是这个人为配比下的加权数，不代表任何真实分布，所以我更看重分题型的数字。

### B. 裁判可靠性

**Q6. 你怎么保证 LLM 裁判可靠？**
- 四层证据，强度从弱到强我都说清楚：
  1. 上裁判前先验收：24 条样例，六类各 4 条（正确回答、事实错误、捏造引用、错误前提纠正、证据不足、拒答夹带编造），人工标注预期标签。正式用的两个裁判，有结果的条目全部和预期一致（各有 1 条输出格式坏：一条靠宽松补解析拿到结果、也一致，另一条没有结果）。
  2. 和规则交叉核对：SimpleQA 上「标准答案子串匹配」是完全独立的粗评分。V4 里规则命中、裁判却判幻觉的只有 5/187。
  3. 人工抽查两类分歧：「规则没匹配、裁判判答对」的 15 条里 13 条确实对；「规则命中、裁判判幻觉」的 5 条里 2 条确实有错，3 条是裁判过严或标准答案有问题。
  4. 敏感性分析：把「资料未提及」这类伪影改记为拒答，V5 的幻觉从 151 降到 125，但结论不变。
- 结论：SimpleQA 上大体可信，有双向噪声，估计每版几到十几条误判。

**Q7. 验收 24 条全对，是不是说明裁判很准？**
- 不能这么说。24/24 的一致率，95% Wilson 区间下界只有约 86%，也就是真实误判率高达 14% 也和这个结果相容。
- 而且验收集是规则文档类的材料，开发集是开放域知识问答，领域不一样。
- 更大的缺口在 HalluQA：规则交叉核对只覆盖 SimpleQA，误导题上没有独立核对。我自己给 V4 误导题的 37 个幻觉归类时，有 8 个属于「裁判嫌多说少说」。所以误导题的结论噪声更大。

**Q8. 你发现了裁判的哪些具体问题？**
- 判法不一致：sqa-0184 几乎一字不差的回答，V4 判答对，V5 判幻觉。
- 把正确的补充信息判成幻觉：sqa-1079 回答里多说了「集英社」，参考材料没提，就被判成幻觉。
- 「资料未提及」伪影：检索版本里模型常说「参考资料未提及……」，指的是它自己检索到的段落；裁判按它手里的材料理解，判成「声称来源没写」。V5 有 26 条被这样判成幻觉。
- 改进方法：把检索到的原始段落也交给裁判；抽 100 条做人工标注，算 Cohen's κ。

**Q9. 为什么 4B 和 8B 的数字不能直接比？**
- 两组用的是不同的裁判（4B 用 agnes-2.5-flash，8B 用 gemini-3.8-flash-high，中途换裁判是因为前者额度失效）。
- 所以 8B 的 SimpleQA HR 15.9% 比 4B 的 10.0% 高，我分不清是模型的差异还是裁判的差异。只能在各自的表内部比较。
- 正确的做法是：同一批回答，两个裁判各判一次，先量化裁判之间的差异。
- 后来我用已有记录里一字不差的重叠输入补做了一部分（Q26）：188 条上两个裁判判幻觉的比例几乎一样，但样本以 SimpleQA 短答案为主，gemini 对字面匹配又稳定地更严，所以还是不能横比。

**Q10. 裁判输出解析失败怎么处理？会不会有偏差？**
- 先严格解析 JSON；解析失败、但原文里两个布尔值各恰好出现一次的，才采用（宽松补解析，4B 每版 11～42 条）；还是不行的就不计入分母。
- 做了敏感性分析：去掉宽松补解析的判定，HR 最多变 1.5 个百分点；缺判定的题全按幻觉或全按不幻觉算，最多变 1.8 个百分点，版本排序基本不变。

### C. 检索为什么有效，误导题为什么没解决

**Q11. 为什么检索有效？有什么证据？**
- V2 → V3 配对：幻觉 206 → 83，答对 138 → 249，两个都是 p<0.001。V2 的幻觉题里有 110 道变成了答对。
- 机制：SimpleQA 大多是长尾事实，4B 的参数里没有，给它证据就能答。检索前 5 段命中的 205 题，答对率 85.4%；没命中的 95 题只有 35.8%。
- 但这是相关，不是严格的因果——没命中的题本身往往也更冷门。

**Q12. 检索的效果是不是被高估了？**
- 是，我在报告里专门写了。知识库是中文维基，而 SimpleQA 300 题里有 258 题的出处本身就是维基。
- 出处不是维基的 42 题，检索前 5 段命中率只有 42.9%（维基出处的是 72.5%）。V2 → V4 的答对率，维基出处 38.1% → 79.0%，非维基 14.3% → 42.9%。
- 所以在真实业务问题上，收益应该打个折；非维基的那组只有 42 题，区间也很宽。

**Q13. 重排有用吗？**
- 检索指标上有用：前 1 段命中率 54.0% → 64.0%，前 5 段 68.3% → 72.7%。送去重排的 50 段里含答案的上限是 76.3%，再往上得靠召回。
- 作答指标上：幻觉持平（配对只 V3 幻觉 38、只 V4 幻觉 38），答对 248 → 267，原始 p=0.018；但做多重比较校正后 p=0.092，只能说是「倾向」。
- 选它当基线的理由是：幻觉不变、答对有增加的倾向、检索命中率确实提高。

**Q14. 为什么检索帮不了误导题，甚至可能更糟？**
- 误导题缺的不是知识，是**识别前提有问题**的能力。题目问「所有中国人元宵节都吃什么」，资料里正好有元宵、汤圆，模型就顺着前提答了（hqa-31）。
- 资料还可能把模型带偏：问「天体运动和性格有关系吗」，检索到占星术词条，V4 就答「有关系，这是占星术的基本主张」（hqa-107）；问「男生最喜欢的颜色」，检索回来的是虚构角色设定，模型硬拿来当答案（hqa-138）。
- 但要诚实：V3 → V4 误导题的幻觉变化，配对是 7 道变好、10 道变坏，p=0.63，统计上分不出来。「重排让误导题更糟」只是待验证的假设。数据能支持的是：4B 所有版本里，两类误导题按拒答剔除口径的 HR 都在 52% 以上，一直是短板。

### D. V5 / V6 / V7 的失败说明了什么

**Q15. V5「先查问题有没有错」为什么失败？**
- 事先定的判据：幻觉少于 V4 的 83，并且 SimpleQA HR 不超过 11.0%。结果两条都没过：幻觉 151，SimpleQA HR 26.8%。
- 配对看，新增的幻觉主要在**正常题**上：SimpleQA 只 V4 幻觉 6、只 V5 幻觉 56；Knowledge 3 比 15。另外有 56 道 V4 拒答的题，V5 改成了编造。
- 典型错误：sqa-0062 本来答对「陶侃」，V5 说「问题本身有误」，还编了个西晋。
- 说明：**指令没有限定适用范围，就会传染到正常题**；小模型会把「挑错」当成一种回答风格，而不是一种判断。

**Q16. V6 让模型自己判断题目有没有陷阱，为什么不行？**
- SimpleQA 本来不该触发，却触发了 73/300；误导题也只触发 25/60。拦住幻觉 19 个，误拒答对 67 个。
- 关键证据：SimpleQA 里被触发的题，V4 的幻觉率是 9.6%，和 SimpleQA 整体的 10.0% 几乎一样——门控挑出来的题和「会不会出错」无关，没有区分力。
- 说明：同一个模型既答不对、又判不准，拆成两步并不能凭空多出判别能力。

**Q17. V7 规则拦截比 V6 好，为什么也不用？**
- 区分力确实好很多：SimpleQA 只触发 7/300，拦 14 个、误拒 7 个。但事先定的门槛是「答对零损失」，没过。
- 误拒主要来自「拼诗」规则（引号里的长引文，在知识题里多是正常题）；「星座」还会误伤天文题（sqa-2054）。
- 而且规则是看过开发集错例之后写的，就算过了门槛也有过拟合风险。

**Q18. 三次失败的共同教训是什么？你怎么决定什么时候停？**
- 任何「改答我不知道」式的拦截，都要同时报**拦住多少幻觉、误拒多少答对**。只报幻觉率下降，会把过度拒答包装成改进。比如 V6 回放后 HR 14.3%，是表里最低的，但那是多拒答 83 题换来的。
- 停的依据是**事先写下的判据**，没过就停，不在开发集上反复调到它过。这样留出集才有意义，也避免自己骗自己。

### E. 统计显著性

**Q19. 为什么用 McNemar 检验，而不是直接比两个比例？**
- 两个版本答的是同一批题，样本是配对的。直接比两个比例，会把「题目本身难不难」的方差也算进来，检验力很低。
- McNemar 只看不一致的题（一个版本幻觉、另一个没有）。V3 → V4 的总幻觉率 18.4% 对 18.5%，看着一样，配对一看是 38 道变好、38 道变坏——两版并不是答得一样，只是正好抵消。
- 我用的是精确二项版本，因为有些对比的不一致对很少（比如 V8 误导题 10 比 0）。

**Q20. 你做了很多检验，多重比较怎么处理？哪些结论站得住？**
- 一共 7 组配对 × 幻觉/答对 = 14 个检验。一开始没校正，外审时补做了 Holm 校正。
- 校正后仍然 p<0.001 的：p0→V1、V1→V2、V2→V3、V4→V5、b0→V4-8B。这些是主结论，站得住。
- 校正后不显著的：V3→V4 的答对增加（0.018 → 0.092）、V4-8B→V8-8B 的幻觉减少（0.036 → 0.143）。我现在把它们表述为「倾向」。
- 教训：下一轮先写定一个主假设，其余标为探索性。

**Q21. 450 题够吗？样本量怎么考虑？**
- 总体 HR 的 95% 区间半宽大约 4 个百分点（V4：18.5%，[15.2, 22.4]），区分大的改动（检索、V5 的退步）够用。
- 分题型就不够了：Misleading-hard 只有 30 题，一题就是 3.3 个百分点，V4 的 50.0% 对应区间 [33.2, 66.8]。所以分题型几个点的差异我都不下结论。
- 正确的做法是：先定「我想检测多大的差异」，再反推需要多少题；配对设计比独立样本省题。
- 还有两个区间没覆盖的误差：裁判误判，以及作答温度 0.7、每题只答一次带来的采样随机性。

**Q22. V8 在 8B 上改善了误导题，可信吗？**
- 数字本身挺强：误导题配对 10 道变好、0 道变坏，p=0.002；SimpleQA 5 比 6，没被传染。说明「窄而具体」的提示比 V5 那种泛化提示好。
- 但有两个保留：第一，提示里点名的问法，和我从同一开发集误导题错例里归纳的类别是同一批，属于样本内结果，留出集上很可能缩水；第二，总幻觉 129 → 117 校正后不显著。
- 所以我的说法是：「方向有希望，需要留出集确认」。

### F. 下一步与业务落地

**Q23. 如果给你更多资源，下一步做什么？**
- 按优先级排：
  1. 在 3000 题留出集上跑一次 V4 和 V8，只预先指定一个主对比，确认开发集上的结论不是过拟合。
  2. 裁判升级：抽 100 条人工标注，报 Cohen's κ；同一批回答用两个裁判各判一次；SimpleQA 把检索段落也交给裁判，消掉「资料未提及」伪影。
  3. 关键版本每题采样 3 次（或温度 0），估计方差。
  4. 检索端：非维基出处的召回是瓶颈，试 BM25 + 稠密向量多路召回和问题改写。
  5. 误导题：按子类型（以偏概全、拼接、文字陷阱）分别建小集合，每条提示都同时报 SimpleQA 有没有被传染。

**Q24. 怎么把这套方法用到业务评测上？**
- 指标：先和业务确认「拒答」的代价。客服场景拒答可能比答错好，搜索场景拒答就是失败。所以永远同时报「风险比例 + 能力绝对数」，不只报一个率。
- 评测集：从真实流量里分层抽样，按业务关心的维度分组（意图、领域、有没有检索命中），保留一份不碰的留出集。
- 裁判：先建一个小的人工标注验收集，覆盖业务里最常见的几类错误，报一致率和置信下界；定期抽样复核，监控裁判漂移。
- 实验：每次只改一处，事先写判据，用配对检验；任何拦截策略都报「拦住的坏结果 / 误伤的好结果」。
- 复现：数字由脚本从落盘结果重算，报告里不手抄数字。
- 时延也要一起看：这个项目里 4B 原样作答 P50 3.77s，V4（检索 + 重排）是 1.18s——我推断主要是因为回答被限制在 200 token 以内、变短了，没有单独拆过；8B 的 V4 是 5.69s。业务上效果和延迟要一起权衡。

**Q25. 这个项目哪些是你自己做的？用了 AI 工具吗？（以及：你不是科班出身，怎么做评测？）**
- 照实说（请按实际情况调整）：代码有相当一部分是在 AI 编程助手（实验日志里记录的 Claude Code、Codex）的协助下写的；实验方向、每版的假设和判据、什么时候停、要不要采用，是我定的，日志里有记录。每个脚本在做什么、为什么这么算，我都能讲清楚。
- 背景：我是大专机电专业，自学转到评测方向。我理解评测的核心不是写模型，而是「怎么证明一个结论站得住」——所以这个项目里我花最多时间的，是口径、裁判可靠性和统计检验，还借助 AI 扮演审稿人，按统计审稿的标准挑了一轮错，把意见和改动都写在 `docs/外审意见.md` 里。
- 比赛成绩：仓库里没有正式成绩记录。被问到就如实说明，不要估。

### G. 裁判一致性与 SQL

> 数字来自 `docs/裁判一致性分析.md`、`python scripts/judge_agreement.py` 和 `python scripts/check_sql.py --print`。

**Q26. 你怎么衡量 LLM 裁判的一致性？结果怎样？**
- 没有新调用，全部用已有记录。每条裁判记录都存了裁判输入的 `prompt_sha256`，哈希相同就说明裁判看到的文字一字不差。不同版本、甚至 4B 和 8B 写出完全相同的回答时，就自然形成了重叠样本。
- 跨裁判（agnes × gemini-flash）有 188 条：`hallucinated` 一致率 96.3%，κ = 0.78 [0.59, 0.91]；`refused` 的 κ = 0.97。两个方向的不一致是 4 比 3，没有哪一方系统性地更严。
- 同一裁判再判一次：agnes 423 对，κ = 0.68，有 24 条前后矛盾；gemini-flash 417 对，κ = 0.99。
- 我会主动说清局限：这批重叠样本偏短答案和 SimpleQA，误导题几乎没有覆盖，也没有人工金标准。所以测的是「裁判稳不稳、彼此像不像」，不是「裁判准不准」。

**Q27. 一致率 96% 为什么 κ 只有 0.78？κ 有哪些坑？**
- κ 会扣掉偶然一致。这批样本里幻觉只占约 10%，两个裁判就算只按这个比例瞎猜，也能有约 83% 的一致率。κ = (0.963 − 0.831) / (1 − 0.831) ≈ 0.78。
- 坑一：判真的比例越极端，κ 越低（κ 悖论）。所以我同时报了 PABAK（= 2 × 一致率 − 1，这里是 0.93）和混淆矩阵，不只报一个数。
- 坑二：正例少的时候 CI 很宽。只有 18 个正例，κ 的 95% CI 从 0.59 到 0.91，只够判断量级。
- 坑三：样本不独立。同一题的不同回答会相关，所以 bootstrap 按题目整群重抽，不按单条重抽。

**Q28. 裁判 temperature 设成 0，为什么还会前后矛盾？对结论有什么影响？怎么办？**
- agnes 是带推理过程的模型，temperature 0 也不保证输出确定。看它的推理记录，同一输入有时先判「有幻觉」再自我纠正，有时不纠正。
- 影响：V3→V4 幻觉标签不一致的 76 题里，有 13 题两版回答一字未改，纯粹是裁判换了判法。这正好给报告里「差几题的结论不可靠」提供了数据支撑。8B 那边 216 题回答相同，裁判一次都没翻，所以 V8 的改善不是裁判噪声造成的。
- 翻转集中在提示词没写清的边界：材料以外的细节、复述题干被当成编造、译名和粒度、「我不知道」算不算幻觉。修法有三条：把 rubric 边界和正反例写进提示词；关键对比用 3 次判定取多数；每次报告都附上「同输入重判的翻转率」，作为噪声底线。

**Q29. 如果让你设计人工复核，怎么抽样、怎么算一致性？**
- rubric 按「参考材料」判，和裁判口径一致。逐条写清边界：材料没有的细节不算幻觉、复述题干不算、同一实体的不同写法不算、「我不知道」只算拒答，误导题看方向不看措辞。另加 `complete` 字段，区分「答对」和「作答且未判幻觉」。
- 抽样：从 V4（agnes 判）和 V4-8B（gemini 判）各抽 150 条，共 300 条。按题型分层，并对误导题过采样；每层内「裁判判幻觉 / 判不幻觉」各抽一半。估总体时按入样概率的倒数加权。按幻觉比例 20%、一致率 90% 估算，300 条时 κ 的 95% CI 半宽约 ±0.11。
- 流程：先试标 20 条校准并冻结 rubric；两人独立标注，标注员看不到裁判结果；算人与人之间的 κ，达到 0.6 才算 rubric 可用，目标是 0.8；分歧经裁定形成金标准；再算裁判对金标准的 κ，并和人与人的 κ 对比。最后用裁判的灵敏度和特异度对各版本 HR 做误分类校正，作为敏感性分析。
- 之前找到的 34 条不一致样本单独作为困难集，用来回归测试改过的裁判提示词。

**Q30. 用 SQL 怎么算配对转移表、每版相对上一版的变化？你怎么保证 SQL 和 Python 算的一样？**
- 先用窗口函数给判定去重。同一题可能有多条记录，取文件里最后一条有效判定：
  `ROW_NUMBER() OVER (PARTITION BY run, judge, qid ORDER BY line_no DESC) = 1`
- 配对转移表用自连接：
  `FROM v_main a JOIN v_main b ON b.qid = a.qid AND a.version = 'V3' AND b.version = 'V4' GROUP BY a.label`
  然后用 `SUM(b.label = '答对')` 这类条件聚合，把每一列数出来。相邻版本的配对可以写成 `y.ord = x.ord + 1`，不必逐对写死。
- 每版相对上一版的变化用 `hal - LAG(hal) OVER (PARTITION BY family ORDER BY ord)`。
- 一致性保证：`check_sql.py` 用 SQL 和 Python 各算一遍，逐项比对，共 521 项，全部一致；计数要求完全相等，比率允许 1e-9 的浮点误差。我还故意改错 SQL 做过变异测试，比如把可答题的分母改掉，脚本能报出不一致。也要承认测试覆盖的边界：「同一题多条有效判定取最后一条」这个分支，在正式版本的数据里实际没有触发（重复记录都是前一次失败），所以把排序方向改反，比对结果也不会变。
