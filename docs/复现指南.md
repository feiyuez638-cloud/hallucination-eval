# 复现指南：从零环境重算全部数字

> 目标：在一台只装了 Python 的机器上，把报告、展示页、面试材料和稳健性分析里的每个数字重新算一遍，并知道每个数字是哪个脚本的哪一行打印出来的。
> 全程只读仓库里已有的作答与裁判判定，**不调用任何模型或付费 API，不需要 GPU，不需要联网**（除了克隆仓库和安装 pytest）。
> 本文里的数字都出自[中文报告](../report/大模型幻觉评测报告.md)、[README](../README.md) 或[稳健性分析](../analysis/稳健性分析.md)；
> 下文每个 `文件:行号` 后面都跟着那一行里的代码片段，`python scripts/check_site_numbers.py` 会逐条核对片段还在不在那一行，行号漂移时报错。

## 1. 准备环境

需要 `Python ≥ 3.9`（CI 用 `3.12`），任意操作系统。重算数字只用标准库；跑测试要装 pytest；重画插图才需要 matplotlib。

用你有权限的方式克隆本仓库（仓库是私有的），然后在仓库根目录：

```bash
python -m venv .venv
```

```bash
source .venv/bin/activate
```

```bash
python -m pip install -r requirements-dev.txt
```

Windows 上第二条换成 `.venv\Scripts\activate`。只想重画插图时再装 `python -m pip install -r requirements.txt`。

## 2. 按顺序重算

每条命令都只读 `eval/runs/`、`data/dev/`、`eval/judge_acceptance.jsonl`，可以重复运行，结果逐字相同。

| 步骤 | 命令 | 产出 | 用时（参考） |
|---|---|---|---|
| ① 报告表格数字 | `python scripts/reproduce_metrics.py` | 打印表 1～3、配对检验、V6 / V7 回放、裁判验收、检索命中率、补充统计；加 `--json out.json` 另存机器可读结果 | 秒级 |
| ② 裁判一致性 | `python scripts/judge_agreement.py` | 跨裁判与同裁判重测的一致率、κ、混淆矩阵 | 秒级 |
| ③ SQL 复现 | `python scripts/check_sql.py` | 临时目录里重建 SQLite，执行 `sql/metrics.sql`，与 ① 逐项比对 | 秒级 |
| ④ 稳健性分析 | `python analysis/robustness.py` | 重新生成 `analysis/稳健性分析.md`（bootstrap、Holm、分层、留一类别、裁判口径与噪声） | 十几秒 |
| ⑤ badcase 画廊 | `python analysis/badcase_gallery.py` | 重新生成 `analysis/badcase画廊.md` | 秒级 |
| ⑥ 数字核对 | `python scripts/check_site_numbers.py` | 展示页、英文报告、面试材料（中英文）、本文的每个数字对照 ①～⑤ 的输出；最后一行应为「全部一致。」 | 十几秒 |
| ⑦ 测试 | `python -m pytest` | `tests/` 下的单元测试与数字回归测试 | 半分钟左右 |
| ⑧ 插图（可选） | `python scripts/make_figures.py` | 重画 `report/figures/` 下的 4 张图，需要 matplotlib | 秒级 |

几个可以对照的结果：③ 的最后一行是「SQL 与 Python 比对：共 521 项，一致 521 项，不一致 0 项」；④ 打印「14 条配对结论中 站得住 9 条、无显著差异 3 条、不确定 2 条」；⑤ 打印「9 类、39 条」。

想确认生成文件没有被手改过，可以写到别处再比对（⑥ 内部就是这样做的）：

```bash
python analysis/robustness.py --out /tmp/robust.md && cmp /tmp/robust.md analysis/稳健性分析.md
```

推到 GitHub 后，`.github/workflows/ci.yml` 会在每次 push 和 PR 上依次跑 ①、④（并比对）、⑥、⑦；它只跑脚本，不部署任何东西。

### 3.4 其他文档

- 展示页 `site/index.html` 的每个数字都用 `data-k` 标了键，键到脚本输出的映射在 `scripts/check_site_numbers.py` 的 `facts()` 里。
- 英文报告、英文 README、一页纸摘要只换语言或压缩，数字必须在中文报告 / README 里出现过；面试讲解稿、深挖 40 问、中文幻灯片的数字必须在中文报告里出现过；英文讲解稿、20 问和英文幻灯片的数字必须在中文报告或稳健性分析里出现过。
- badcase 画廊与稳健性分析是脚本输出，核对方式是重新生成后逐字比对。

## 4. 测试覆盖什么

| 文件 | 内容 |
|---|---|
| `tests/test_reproduce_metrics.py` | Wilson、McNemar、Holm、p 值格式、双标签恒等式、宽松补解析的单元测试；表 1～3、配对、Holm、回放、验收集、检索命中率的数字回归测试 |
| `tests/test_badcase_gallery.py` | 已提交的画廊等于脚本输出；预期转移写错时脚本拒绝生成 |
| `tests/test_robustness.py` | 百分位、编码、翻转抽样、临界题数的单元测试；基准检验与 `reproduce_metrics.py` 逐项相同；分层计数加总等于总体；固定种子结果可复现；结论档位与关键数字的回归测试 |
| `tests/test_check_site_numbers.py` | 整体核对通过；造一个没有来源的数字、漂移的行号、缺失的链接，各项检查都能抓到 |

## 5. 复现不了的部分

重新跑模型推理（作答、检索、裁判）需要本地 Ollama、维基知识库（约 4.5 GB，`rag/fetch_wiki.py` + `rag/build_kb.py` 构建）、重排模型和裁判 API，这些都不在仓库里。本文复现的是「从已落盘的作答与判定到报告数字」这一段；作答和判定本身是一次性的记录，重跑会因为采样温度与裁判自身不稳定而略有不同（报告 §7 第 5 条、稳健性分析 §6）。
